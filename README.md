Изначально пробовал решить задачу используя только BM25, но решил что этого будет недостаточно. BM25 игнорирует смысл и контекст, не понимает  синонимов. Для решения этой  проблемы решил использовать intfloat/multilingual-e5-small и дообучить ее на предоставленных данных. Валидацию проводил путем деления train.parquet на уникальные запросы. Из данных использовал train.parquet (497 673 пары) для обучения и валидации, enchmark_queries.parquet для финального ответа и benchmark_items.parquet в качестве корпуса, по которому идет поиск.В качестве признаков запроса брал search_query и  search_infm_params_text, в качестве признаков  объявления item_title_raw, item_infm_params_text и item_description_raw. Описание обрезал до 500 символов для оптимизации, чтобы модель не тратила время на длинные тексты. Выбрал именно эти поля, потому что они содержат текст, релевантный запросу, а числовые признаки ,по моему мнению,  вроде цены, рейтинга и т.д. на этапе кандидатогенерации не помогают. Столкнулся с проблемой, что BM25 не понимает словоформы. Для решения этой проблемы использовал pymorphy3. Через него проводил лемматизацию слов. Далее решил использовать hard negatives чтобы модель могла распознавать похожие, но нерелевантные объявления.Обучение разбивал на чанки, потому что весь датасет не влезал в память целиком Так как e5 путает похожие объявления, решил создать небольшой cross encoder, так как он уже смотрит на запрос вместе с объявлением. Конечным результатом я не удовлетворён. В самом начале, на этапе обучения первой модели и экспериментов с ней, чтобы оптимизровать,   допустил несколько критических ошибок (очень маленькое количество эпох,весами и тд), из-за которых потерял много времени.
